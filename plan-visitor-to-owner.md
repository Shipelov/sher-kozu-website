# Полная цепочка: Посетитель → Владелец

## Резюме

Цель — выстроить непрерывный путь нового человека от первого визита на сайт до полноценного участия в экосистеме фермы. Путь должен быть понятным, не требовать ручного вмешательства админа на этапе регистрации и при этом давать администратору полный контроль и аналитику на каждом шаге.

## 2. Что нужно доработать (выявленные пробелы)

### 2.1. Навигация и авторизация в Navbar

Сейчас Navbar не показывает состояние авторизации. Кнопка «Личный кабинет» ведёт на `/dashboard` без проверки, авторизован ли пользователь. Нет кнопки «Войти / Выйти».

**Решение:**
- Добавить в Navbar состояние авторизации через `useAuth()`
- Неавторизованный: кнопка **«Войти»** (ведёт на `getLoginUrl()`)
- Авторизованный: аватар/имя + dropdown с «Мой кабинет», «Выйти»
- Админ: дополнительный пункт «Админ-панель»

### 2.2. Onboarding после первой авторизации

Сейчас после OAuth-callback пользователь попадает на Dashboard, который показывает «гостевой» режим с подсказками. Но нет явного **onboarding-потока**, который объяснит новому пользователю, что делать дальше.

**Решение:**
- После первой авторизации (пользователь без ownership) показать **Welcome-экран** с 3 шагами:
  1. «Выберите животное в каталоге»
  2. «Выберите долю участия»
  3. «Дождитесь подтверждения фермы»
- Кнопка «Начать» ведёт в каталог животных
- Welcome-экран показывается только один раз (флаг `onboardingCompleted` в таблице users)

### 2.3. Статус «Ожидает оплаты» для владельца

Сейчас после `purchaseShare` создаётся ownership со статусом `pending_payment`, но владелец не видит чёткого объяснения, что происходит и что от него ожидается.

**Решение:**
- В Dashboard при `pending_payment` показать карточку с инструкцией по оплате
- Контактные данные для связи с фермой
- Таймер или дедлайн (опционально)
- Push-уведомление админу о новой заявке на долю

### 2.4. Уведомление админу о новом владельце

Сейчас при `purchaseShare` нет push-уведомления админу. Админ узнаёт о новых заявках только заходя в панель.

**Решение:**
- При `purchaseShare` отправлять `notifyOwner` с данными: имя пользователя, животное, доля, дата
- В AdminHub показать счётчик «Новые заявки» с бейджем

### 2.5. Аналитика для админа: воронка конверсии

Сейчас AdminHub показывает только количество животных и клубных данных. Нет аналитики по пользователям.

**Решение:**
- Добавить в AdminHub секцию **«Аналитика пользователей»**:
  - Всего зарегистрированных
  - Ожидают оплаты (pending_payment)
  - Активные владельцы (active)
  - Ожидают подтверждения плана (pending_approval)
  - Конверсия: зарегистрированные → владельцы
- Таблица последних регистраций с датой, статусом, животным

## 3. Целевой User Journey

```
┌─────────────────────────────────────────────────────────────────┐
│  1. ПОСЕТИТЕЛЬ (неавторизован)                                  │
│     Home → Каталог → Профиль животного → Выбор доли             │
│     Navbar: [Войти]                                             │
│     CTA: «Стать владельцем» → redirect на OAuth                 │
├─────────────────────────────────────────────────────────────────┤
│  2. АВТОРИЗАЦИЯ                                                 │
│     Manus OAuth → callback → redirect на профиль животного      │
│     (с сохранённой долей в URL ?share=10)                        │
├─────────────────────────────────────────────────────────────────┤
│  3. ПЕРВЫЙ ВИЗИТ (авторизован, нет ownership)                   │
│     Welcome-экран: 3 шага → «Начать» → Каталог                  │
│     Navbar: [Аватар ▾] → Мой кабинет / Выйти                   │
├─────────────────────────────────────────────────────────────────┤
│  4. БРОНИРОВАНИЕ ДОЛИ                                           │
│     Профиль животного → Подтвердить долю → purchaseShare        │
│     Статус: pending_payment                                     │
│     → Push-уведомление админу                                   │
│     → Dashboard: карточка «Ожидает оплаты» + инструкция         │
├─────────────────────────────────────────────────────────────────┤
│  5. ПОДТВЕРЖДЕНИЕ АДМИНОМ                                       │
│     Админ → AdminAnimals → Подтвердить оплату → active          │
│     → Уведомление владельцу (опционально)                       │
├─────────────────────────────────────────────────────────────────┤
│  6. АКТИВНЫЙ ВЛАДЕЛЕЦ                                           │
│     Dashboard: животное, доля, summary cards                    │
│     → Выбор продуктового плана → pending_approval               │
│     → Админ подтверждает → confirmed → график доставки          │
│     → Чат с фермой                                              │
│     → Клуб: события, визиты                                     │
├─────────────────────────────────────────────────────────────────┤
│  7. АНАЛИТИКА АДМИНА                                            │
│     AdminHub: воронка, счётчики, последние регистрации          │
│     AdminAnimals: доли, планы, чаты, лог                        │
└─────────────────────────────────────────────────────────────────┘
```

## 4. План реализации

### Блок A: Navbar с авторизацией (1 итерация)

Обновить `Navbar.tsx`:
- Интегрировать `useAuth()` для определения состояния
- Неавторизованный: кнопка «Войти» вместо «Личный кабинет»
- Авторизованный: аватар + имя + dropdown (Мой кабинет, Админ-панель для admin, Выйти)
- Мобильное меню: те же пункты

### Блок B: Welcome-экран для новых пользователей (1 итерация)

- Добавить поле `onboardingCompleted` в таблицу `users` (boolean, default false)
- Создать компонент `WelcomeOnboarding.tsx` с 3 шагами
- В Dashboard: если `!onboardingCompleted && !ownership` → показать Welcome
- Кнопка «Начать» → ставит `onboardingCompleted = true` → redirect в каталог
- Кнопка «Пропустить» → ставит `onboardingCompleted = true` → остаётся на Dashboard

### Блок C: Уведомления о новых заявках (1 итерация)

- В `purchaseShare` добавить `notifyOwner()` с данными заявки
- В AdminHub добавить бейдж «Новые заявки» (count pending_payment)
- В AdminAnimals подсветить животных с pending_payment долями

### Блок D: Улучшение Dashboard для pending_payment (1 итерация)

- При `pending_payment` показать информативную карточку:
  - «Ваша заявка на долю X% животного Y принята»
  - «Свяжитесь с фермой для оплаты» + контакты
  - Статус-бар: Заявка → Оплата → Активация
- Убрать guest-preview секции, показать реальный статус

### Блок E: Аналитика пользователей в AdminHub (1 итерация)

- Создать серверную процедуру `adminAnalytics.userFunnel`:
  - Всего пользователей
  - С ownership (по статусам)
  - С продуктовыми планами (по статусам)
  - Последние 10 регистраций
- В AdminHub добавить секцию «Воронка пользователей» с карточками и таблицей

### Блок F: Тесты и стабилизация (1 итерация)

- Unit-тесты для onboarding flow
- Unit-тесты для уведомлений при purchaseShare
- Unit-тесты для аналитики
- Smoke-тест полной цепочки: регистрация → выбор → бронирование → подтверждение → план

## 5. Приоритеты

| Приоритет | Блок | Влияние |
|-----------|------|---------|
| P0 | A: Navbar с авторизацией | Базовая навигация, без неё цепочка разорвана |
| P0 | D: Dashboard для pending_payment | Владелец не понимает, что делать после бронирования |
| P1 | C: Уведомления о заявках | Админ не узнаёт о новых владельцах |
| P1 | B: Welcome-экран | Онбординг новых пользователей |
| P2 | E: Аналитика | Операционная прозрачность для админа |
| P2 | F: Тесты | Стабильность цепочки |

## 6. Оценка трудозатрат

Общий объём: **6 итераций** (блоки A–F). Каждый блок — самостоятельная единица с чекпоинтом. Можно реализовать последовательно или параллельно по приоритетам.
