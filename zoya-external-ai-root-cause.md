# Root-cause: регулярные отказы внешнего AI Зои

**Дата:** 6 сентября 2026 года  
**Автор:** Manus AI

## Вывод

Проблема состоит не в постоянной недоступности Cloudflare Worker. Production probes вернули HTTP 200 за 1,0–1,4 секунды как для минимального запроса, так и для payload размером 3718 символов. Cloudflare Dashboard показывает 67 вызовов Worker и 0 Worker errors за последние 24 часа.

Фактический отказ возникает **после успешного transport-вызова**: приложение ожидает сложный объект `ZoyaStructuredResponse`, а native Workers AI модель возвращает нестабильную форму, неполный JSON или текст, который не проходит строгую серверную проверку. Пользователь видит один общий fallback, поскольку точный `reason code` не сохраняется.

## Подтверждённые дефекты

| Уровень | Подтверждённое наблюдение | Последствие |
|---|---|---|
| Model identity | VDS отправляет и диагностирует `gpt-4o-mini`, но Worker фактически использует native `@cf/meta/llama-3.1-8b-instruct-fast` | Диагностика сообщает не фактическую модель и выбирает неверный capability contract |
| Structured output | Production-like strict-schema вызов возвращал `content: undefined/null`; schema-in-prompt ответы содержали trailing comma, числовые строки, пропущенные поля и `finish_reason=length` | Parser вынужден repair/default, а строгая схема периодически отклоняет ответ |
| Contract complexity | Модель должна вернуть summary, facts, answer, mealPlan, items, КБЖУ, substitutions, warnings, sources и referenceNote | 8B-модель отвечает одновременно за язык, структуру, факты и арифметику; вероятность нарушения хотя бы одного поля высока |
| Validator | Ответ отклоняется при meal-plan incompleteness, неизвестном продукте, отклонении КБЖУ/доли, invalid evidence ID или unsafe medical claim | Даже содержательно полезный текст полностью скрывается от пользователя |
| Observability | Error-ветка не сохраняет failed attempt и выдаёт общий текст `не прошёл проверку фактов или расчётов` | Невозможно восстановить точный прошлый reason code по истории |
| Transport | Production `system.aiDiagnostics` и `system.mashaAiDiagnostics` успешны; Worker errors = 0 | Transport не является основной причиной показанного validator-fallback |

## Почему текущий контракт архитектурно нестабилен

Cloudflare поддерживает JSON Mode для `@cf/meta/llama-3.1-8b-instruct-fast`, но прямо предупреждает, что сложная JSON Schema не гарантируется; при невозможности выполнить схему провайдер должен возвращать отдельную ошибку. JSON Mode также не поддерживает streaming.[1]

Кроме того, native `@cf/...` модели используют bare JSON Schema, тогда как OpenAI partner-модели используют envelope `{name, schema}`. Текущий Worker маскирует native модель под OpenAI-compatible `gpt-4o-mini`, поэтому приложение не может корректно выбрать контракт по реальной capability модели.[2]

## Выбранная архитектура

| Вариант | Плюсы | Риски | Решение |
|---|---|---|---|
| Оставить сложный JSON и смягчить валидатор | Минимум изменений | Сохраняет зависимость от нестабильного nested JSON; ошибки арифметики и продуктов остаются | Отклонён |
| Исправить Worker и включить native JSON Mode | Улучшает синтаксическую форму | Cloudflare не гарантирует сложную схему; JSON Mode не поддерживает streaming; 8B-модель всё ещё генерирует факты и расчёты | Недостаточно как основное решение |
| Перейти на крупную partner-модель через AI Gateway | Выше качество и schema adherence | Новая стоимость, внешняя зависимость и необходимость отдельной конфигурации; критический контур всё равно остаётся в AI | Возможная будущая оптимизация, не базовая надёжность |
| Серверный draft + AI только для plain-text редакции | Факты, расчёты и доступность не зависят от модели; простой контракт; безопасный fallback | Требует разделить доменные генераторы по intent | **Выбран** |

Внешний AI больше не должен генерировать критическую структуру ответа.

1. **Сервер формирует проверенный draft.** Профиль, confirmed-продукты, RAG evidence, расчёты, источники и safety-ограничения собираются без AI.
2. **Меню и КБЖУ остаются детерминированными.** Модель не может добавлять продукты, граммовки, значения КБЖУ или менять долю продукции.
3. **Медицинские red-line ответы детерминированы.** Внешняя модель не принимает решения по аллергии и противопоказаниям.
4. **Для обычных вопросов AI получает готовый evidence draft и выполняет только языковую редактуру.** Контракт — простой plain text с коротким token budget, а не вложенный JSON.
5. **При любом AI-сбое пользователь получает проверенный draft.** Ошибка модели не превращается в отказ функции.
6. **Каждая попытка получает безопасный reason code.** Логируются intent, mode, outcome, stage, latency и counts; prompt, профиль, сообщение и секреты не записываются.

Эта схема сохраняет естественность ответов, но устраняет внешнюю модель из контура фактов, расчётов и доступности основной функции.

## Реализованное исправление

Production runtime больше не содержит сложный nested-JSON prompt, parser, repair-слой или `response_format` для Зои. Библиотека JSON repair удалена как ненужная.

| Сценарий | Новый runtime | Зависимость от внешнего AI |
|---|---|---|
| Персональное меню и КБЖУ | Server-owned deterministic planner формирует продукты, граммовки, суммы, долю фермерской продукции, замены и источники | **Нет** |
| Неполный запрос персонального меню | Server-owned draft/уточнение; запрос не проваливается в общий AI-контур | **Нет** |
| Медицинская red line | Серверный ответ по обязательному verified evidence | **Нет** |
| Обычный информационный вопрос | Сервер сначала формирует verified draft; AI может только переписать его простым текстом без новых фактов и чисел | Необязательная |
| Ошибка/timeout/пустой/JSON-подобный ответ модели | Пользователю возвращается исходный server draft | Функция сохраняется |

Для tRPC и SSE добавлена единая безопасная telemetry: `intent`, `contextStatus`, `mode`, `outcome`, `reasonCode`, `aiLatencyMs`, `totalLatencyMs`, количество evidence/confirmed-продуктов и коды server validation. Запрос пользователя, prompt, профиль, email, названия персональных ограничений и секреты не логируются.

Admin diagnostics теперь показывает для Cloudflare `worker-managed (request alias: gpt-4o-mini)`, а не выдаёт request alias за фактическую native-модель Worker.

После публикации показанный пользователем fallback `внешний ответ не прошёл проверку фактов или расчётов` больше не должен возникать для персонального меню: внешняя модель в этом сценарии не вызывается и не проходит server validator.
