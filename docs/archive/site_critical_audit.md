# Аудит критических рисков сайта «Шерь Козу»

## Текущее состояние

Проект находится в рабочем состоянии: dev-сервер запущен, TypeScript не показывает активных ошибок, а Vitest ранее проходил успешно со счётом 106/106. При этом в логах и структуре проекта остаются **несколько системных рисков**, которые могут повторно приводить к критическим сбоям в production-like сценариях.

## Ключевые найденные риски

| Приоритет | Область | Проблема | Симптом | Почему это критично |
|---|---|---|---|---|
| P1 | OAuth / сессия | В `server/_core/oauth.ts` callback по-прежнему редиректит на `/`, а не восстанавливает `origin + returnPath` из state | После логина пользователь может попадать не туда, а в preview / multi-origin сценариях возможны повторные проблемы с сессией | Это влияет на стабильность входа и возврат в защищённые разделы |
| P1 | Глобальная auth-обработка | В `client/src/main.tsx` ещё используется глобальный redirect-перехватчик для всех query/mutation ошибок | При нестабильных auth-запросах или фоновых ошибках возможен неожиданный переход на логин | Это затрагивает весь сайт, а не одну страницу |
| P1 | AdminClub / сложный state | В `AdminClub.tsx` остаётся очень большой и сложный файл с множеством `useEffect`, `setLocation`, фильтров, URL-state и Bitrix24-секций | Даже после фикса зависания остаётся высокий риск новых циклов перерендера и регрессий | Это уже проявлялось как зависание `/admin/club` |
| P1 | Bitrix24 pilot не завершён по roadmap | В `todo.md` остаются незакрытые пункты по integration layer, admin monitoring и checkpoint-валидации | Возможны частично реализованные или хрупкие сценарии CRM-пилота | Это может ломать lead-flow и админский мониторинг |
| P2 | Исторические server errors в логах | В логах остаются ошибки `No values to set` и `TransformError` как следы недавних падений | Даже если активная сборка сейчас зелёная, часть сценариев уже была нестабильной | Нужна полная повторная валидация, чтобы исключить скрытые ветки |
| P2 | Покрытие тестами | Тесты есть, но по признакам кода не покрывают весь auth redirect flow, multi-origin OAuth callback и крупные state-transition сценарии `/admin/club` | Некоторые критичные баги проявлялись только в runtime, а не в unit-тестах | Это повышает риск повторного появления тех же ошибок |
| P2 | Незавершённые publish-critical задачи | В `todo.md` всё ещё есть незакрытые publish-critical элементы вне текущего bugfix-pass | На опубликованном домене могут обнаружиться проблемы, не воспроизводимые в dev-preview | Это мешает считать сайт полностью устойчивым |

## Детализация наблюдений

На основании свежей проверки окружения видно, что сервер сейчас работает стабильно, а TypeScript и language service не сообщают об активных ошибках. Однако в логах всё ещё присутствуют исторические ошибки, связанные с авторизацией и трансформацией сборки, поэтому нельзя считать систему полностью санированной без повторного прохода по критическим сценариям.

Особенно важно, что архитектурный риск сместился из разряда «явная ошибка компиляции» в разряд **хрупкой сложности состояния**. Это касается прежде всего `/admin/club`, где в одном компоненте сосредоточены CRUD-таблицы, URL-state, лог действий, экспорт, Bitrix24-мониторинг, фильтры, пагинация и множественные эффекты. Даже если текущий баг уже исправлен, такой объём логики в одном файле остаётся главным источником будущих критических сбоев.

Отдельным риском остаётся OAuth-flow. Из анализа кода видно, что callback всё ещё использует упрощённый редирект на корень сайта. Для среды с preview-доменами, защищёнными маршрутами и возвратом пользователя в конкретный раздел это слабое место. Именно такие детали часто вызывают «плавающие» ошибки входа, которые сложно поймать обычным unit-тестом.

## Приоритетный план исправления

| Этап | Приоритет | Что исправить | Практический результат |
|---|---|---|---|
| 1 | P1 | Привести OAuth callback и клиентский redirect flow к единой схеме `origin + returnPath` | Стабильный вход без случайных выбросов и неверных редиректов |
| 2 | P1 | Разделить `AdminClub.tsx` на подкомпоненты: CRUD tabs, Activity tab, Bitrix24 tab, URL-state controller | Снижение риска зависаний и упрощение отладки |
| 3 | P1 | Завершить и формально закрыть незавершённые Bitrix24 roadmap-задачи, особенно monitoring/integration validation | Предсказуемая работа partner lead pipeline |
| 4 | P2 | Добавить Vitest для auth redirect edge-cases, OAuth callback state parsing и guard-логики `/admin/club` | Ловля регрессий до ручной проверки |
| 5 | P2 | Провести полный smoke-pass на опубликованном домене по маршрутам Home → Dashboard → Animal Profile → Product Tracker → Club Feed → AdminClub | Проверка реального поведения вне dev-preview |
| 6 | P2 | Очистить и нормализовать проблемные лог-точки: `console.error`, server error branches, fallback UX для Bitrix24/API failures | Более контролируемое поведение при сбоях внешних интеграций |

## Рекомендуемый порядок работ

Сначала стоит закрыть **авторизацию и redirect architecture**, поскольку это горизонтальный риск для всего сайта. Затем нужно заняться **декомпозицией AdminClub**, потому что именно там уже проявлялись критические runtime-проблемы. После этого имеет смысл завершить Bitrix24 pilot как единый контур: серверный flow, мониторинг, retry-логика и проверка админских сценариев. Завершающим шагом должен стать расширенный тестовый и smoke-pass на опубликованном домене.

## Вывод

На данный момент сайт выглядит **рабочим, но не полностью стабилизированным**. Критическая зона риска сместилась в три области: **OAuth/redirect flow**, **монолитная сложность `/admin/club`**, и **незавершённые Bitrix24 pilot-сценарии**. Следующий правильный шаг — не точечные косметические правки, а короткий стабилизационный спринт, который уменьшит вероятность повторных критических ошибок по всей системе.
