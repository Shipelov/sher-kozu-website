# Устойчивость общего AI-контура Зои

## Установленная причина

`invokeLLM()` выполнял `fetch()` без `AbortSignal` и без тайм-аута. Оба маршрута Зои ожидали этот Promise без общего deadline. SSE открывал соединение, отправлял только метаданные, а первый содержательный chunk появлялся лишь после полного ответа внешней модели. Клиент также не имел собственного тайм-аута. Поэтому остановившийся Worker или Workers AI приводил не к контролируемой ошибке, а к визуальному зависанию.

## Контракт исправления

| Уровень | Ограничение | Поведение при отказе |
|---|---:|---|
| Core `invokeLLM` | 90 секунд по умолчанию; переопределяется вызывающим кодом | Abort сетевого запроса |
| Zoya primary attempt | не более 16 секунд | Один retry только для timeout/429/5xx/сетевой ошибки |
| Zoya retry | не более 9 секунд и только в остатке общего бюджета | Контролируемый fallback |
| Общий Zoya deadline | 26 секунд | tRPC и SSE возвращают одинаковый понятный ответ |
| Клиент ZoyaChat | 45 секунд | Abort reader-loop и локальное сообщение вместо вечного spinner; запас на доставку уже сформированного ответа |

SSE должен отправлять heartbeat во время ожидания, прекращать upstream-запрос при закрытии браузером соединения и всегда завершаться `[DONE]`, если клиент ещё подключён. Поддерживаемые запросы дневного меню с долей молочной продукции обрабатываются детерминированно по confirmed-продуктам даже без слов о спорте; это не подмена общего fallback набором фразовых шаблонов, а отдельный предметный сценарий с проверяемыми бизнес-данными.
