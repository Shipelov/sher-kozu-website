# План перехода Club Feed и Product Tracker на реальные данные

Сейчас обе страницы уже визуально оформлены, но ещё опираются на локальные демонстрационные массивы. Следующий шаг состоит в том, чтобы перенести их на единый серверный слой: данные должны читаться через tRPC и базу, а пользовательский интерфейс должен сохранить текущий visual storytelling, маршруты и premium-подачу. При этом для надёжности полезно оставить серверный fallback, который вернёт курированный стартовый контент, если база временно недоступна или новые таблицы пока пусты.

| Направление | Что добавить | Как использовать в UI |
| --- | --- | --- |
| **Product Tracker** | Таблицы для обзорных метрик, истории доставок, состава партии и шагов происхождения | Заменить локальные `composition`, `monthlyData`, `deliveries`, `originSteps`, `routeNotes` данными из `tracker.getOverview` |
| **Club Feed** | Таблицы для постов, событий, витрины участников, статистики и уведомлений | Заменить локальные `posts`, `events`, `members`, hero-статистику и notification-блок данными из `club.getFeed` |
| **Серверный слой** | Новые helper-функции в `server/db.ts` и новые read-процедуры в `server/routers.ts` | Дать страницам единый источник данных через `trpc.*.useQuery()` |
| **Надёжность** | Fallback-данные на сервере при пустой БД | Сохранить работу страниц и демо-качество интерфейса даже до наполнения админкой |
| **Тесты** | Vitest для helper-функций и source-smoke для страниц | Проверить, что UI использует tRPC и не откатился к локальным константам |
